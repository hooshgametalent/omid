# قانون تناسب فرایند با اندازهٔ کار

هدف این قانون جلوگیری از gate و handoff غیرضروری است.

## مسیر سریع برای کارهای روتین

کارهای محلی، کم‌ریسک و برگشت‌پذیر مانند نصب اولیهٔ framework، نصب dependency تأییدشده، اجرای formatter، ساخت asset، خواندن نسخه‌ها و اجرای test موجود باید با یک مالک و در یک جریان انجام شوند:

1. بررسی کوتاه پیش‌نیاز مستقیم همان command؛
2. اجرای محلی؛
3. بررسی exit code و خروجی واقعی؛
4. گزارش فایل‌های تغییرکرده و نتیجه.

برای این کارها orchestration چندایجنتی، phase gate کامل، threat model، بازبینی مستقل یا approval میانی لازم نیست، مگر command به blocker واقعی برسد.

## زمان استفاده از متخصص‌ها و gateها

هماهنگی چندایجنتی فقط وقتی لازم است که کار شامل یکی از این موارد باشد:

- تصمیم معماری یا انتخاب package پراثر و بلندمدت؛
- schema، migration یا تغییر داده؛
- authentication، authorization، IAM/RBAC یا tenant isolation؛
- ورودی حساس، امنیت، حریم خصوصی یا integration بیرونی؛
- تغییر بزرگ رابط، SEO عمومی، accessibility یا performance gate؛
- production، deploy، CI/CD، infrastructure یا عملیات سخت‌برگشت؛
- ابهام محصولی که نتیجهٔ پیاده‌سازی را عوض می‌کند.

## قواعد توقف

- بررسی پیش‌نیاز نباید به پروژهٔ جداگانه تبدیل شود؛ فقط موارد لازم برای command جاری بررسی می‌شوند.
- نبود اطلاعات غیرمرتبط مانع کار روتین نمی‌شود.
- در blocker واقعی، همان مالک متوقف می‌شود و خطا و یک اقدام بعدی روشن را گزارش می‌کند؛ ایجنت‌های متعدد برای تکرار همان بررسی فراخوانی نمی‌شوند.
- هیچ کاری صرفاً برای رعایت تشریفات به agent دیگر handoff نمی‌شود.
